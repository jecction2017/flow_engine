# 平台简介

## 概述

flow_engine 是一套**流程编排与运行平台**：把分散的业务步骤（脚本、HTTP 调用、消息收发、查表逻辑等）组织成**可版本化、可测试、可部署**的流程（Flow），在指定环境（Profile）下受控执行。

适合场景包括：告警处置流水线、数据同步任务、指标特征计算、多系统集成编排、自动化测试验证等。

---

## 你能用它做什么

| 能力 | 说明 |
|------|------|
| **可视化编排** | 在 Flow Studio 用节点树设计 task / loop / subflow，配置执行策略与容错 |
| **脚本驱动** | 节点使用 Starlark（Python 风格子集）编写，内置 HTTP、Kafka、ES、Lookup 等集成 |
| **受控调试** | 试运行、节点调试、脚本调试均在 debug 模式下执行，默认抑制副作用 |
| **自动化测试** | 测试中心用 lookup 表驱动用例，支持断言、Mock、批次对比 |
| **生产部署** | 运行中心创建部署，支持 cron 调度、Kafka 订阅、多 Worker |
| **可观测性** | 运行记录提供 Spans 链路、指标摘要、分级日志 |
| **环境隔离** | Profile + 数据字典 + Lookup 实现 dev/staging/prod 配置分离 |

---

## 典型使用方式

```
设计流程 → 试运行验证 → 编写测试方案 → 提交版本 → 创建部署 → 监控运行
```

1. 在 **Flow Studio** 编辑流程拓扑与节点脚本，保存草稿并提交版本。
2. 用 **试运行** 或 **测试中心** 在受控模式（debug）下验证行为。
3. 在 **运行中心** 创建**部署**，绑定已提交版本、Profile 与调度方式，由 **Worker** 执行。
4. 在 **运行中心** 查看运行记录、链路（Spans）与日志，排查问题。

## 界面一览

顶部 8 个 Tab：

| Tab | 用途 |
|-----|------|
| **Flow Studio** | 流程设计与试运行 |
| **运行中心** | 部署、运行记录、工作节点 |
| **测试中心** | 测试方案、批次、断言 |
| **能力与脚本** | 用户脚本、内置函数注册表 |
| **环境配置** | Profile 与系统能力策略 |
| **数据字典** | YAML 模块树与密钥 |
| **Lookup** | 表格式配置/测试数据 |
| **帮助文档** | 本帮助站点 |

---

## 安全边界（必读）

以下入口服务端**固定为调试模式**，默认抑制 HTTP、Kafka 等副作用调用：

- 流程试运行
- 节点调试
- 用户脚本调试
- 测试中心运行

若要在真实环境产生副作用，须通过**部署**以 production 或 shadow 模式运行，并配置好能力策略。
