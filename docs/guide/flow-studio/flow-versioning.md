# 流程版本

## 概述

Flow Studio 区分 **草稿**（可继续编辑）与 **已提交版本**（V1、V2…，不可变）。试运行可用草稿或版本；**部署与生产运行必须使用已提交版本**。

---

## 草稿

- 在编辑器中随时修改节点、脚本、策略
- **保存草稿** 持久化到服务端，不产生新版本号
- 多人协作时以服务端草稿为准（按产品协作模型）

---

## 提交版本

1. 确认草稿试运行通过
2. 点击 **提交版本**
3. 系统生成递增版本号（V1、V2…）
4. 该版本内容**不可再修改**；后续改动在新草稿上进行，再次提交产生 V(n+1)

### 版本用途

| 消费者 | 行为 |
|--------|------|
| 试运行 | 可选草稿或指定版本 |
| 部署 | 必须选 Vn |
| 测试方案 | 绑定版本通道（如 latest Vn 或固定 V2） |

---

## YAML 导入 / 导出

Flow Studio 支持流程定义的 YAML 导入导出，便于：

- 备份与版本管理（Git）
- 批量迁移环境
- 代码审查

### 建议流程

```
导出 YAML → 编辑/审查 → 导入为新流程或覆盖草稿 → 试运行 → 提交版本
```

导入后检查节点 id、name 唯一性及脚本方言合法性。

---

## 版本切换与部署

- 部署创建时选择目标版本
- 流程升级：提交 V(n+1) 后编辑部署切换版本
- 回滚：部署切回旧版本号即可（无需改流程定义）

---

## 常见问题

**Q: 提交了还能改吗？**  
A: 已提交版本不可变；修改在草稿进行并提交新版本。

**Q: 部署用的哪个版本？**  
A: 部署配置中显式绑定的 Vn，不会自动跟随草稿更新。

**Q: 测试方案如何跟版本？**  
A: 方案配置版本通道；流程提交新版本后按通道规则解析（如 always latest）。
